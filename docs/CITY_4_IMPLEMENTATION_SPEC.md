# Kingdom Garden Junior — Little Living City 4.0 實作規格

**交付狀態：設計與工程規格，不是已完成或已部署的 City 4.0 遊戲。**

本次只新增這份文件，不修改目前可玩的城市、閱讀、寫字、數學或使用者存檔。以下標示的功能與驗收項目，除「現況」外，均為待實作要求；不代表已通過測試。

## 1. 產品方向與核心決策

**把城市做成一張會自己動的玩具遊戲板，而不是一張需要追車的大地圖。**

孩子的操作循環：

**閱讀／寫字／數學 → 獲得既有金幣 → 買收藏品 → 放入城市 → 看見自動行駛和互動。**

本版鎖定的改變：

1. 城市全貌在單一主畫面看完，不再使用超大捲動地圖、迷你地圖或自動追車鏡頭。
2. 可以同時放置多台已擁有的車，不再只有一台被選中的車能行駛。
3. 車子自行挑選適合的目的地、沿道路行駛、進入停靠區互動，再開始下一趟。
4. 建築與收藏品由孩子放入、移動或收回收藏。購買、擁有與放置是三件不同的事。
5. 購買越多、放置越多，城市的外觀和可發生的互動越豐富，但不藉此產生無限金幣。
6. 保留現有金幣、資產、閱讀紀錄、寫字成果、數學貼紙，以及獨立的 5,000 幣測試模式。

第一版不做自由地形編輯、道路建造、碰撞損壞、燃料、多人連線、真正 3D 物理或付費抽獎。這些都不是讓城市好玩的必要條件。

## 3. 單畫面城市：8 區，而不是 16 個需要捲動的地標

### 3.1 畫面構成

上方只保留返回學習、金幣、暫停城市及設定。中間是完整城市遊戲板；底部是「我的車／建築／裝飾／商店」操作列。

移除巨型標題橫幅、四個大型統計卡片、迷你地圖、跳轉目的地清單，以及主玩法中的 Drive here 按鈕。這些佔用空間卻不是孩子的核心操作。

- 正常探索狀態不要求水平或垂直捲動地圖。
- 不在車子移動時改變鏡頭位置或缩放。
- 選單與收藏清單可以獨立捲動；它們不能讓整張城市一起移動。
- 詳細介紹只在選取物件後開啟；關閉後仍回到同一個總覽。
- 不以 `user-scalable=no` 禁止使用者的瀏覽器輔助縮放。

### 3.2 區域與資產對應

| 區域 | 常設內容 | 可放入的既有資產 | 主要互動 |
|---|---|---|---|
| Home Lane | Pip 的家 | `village`，原有花朵 | 家用車接送、角色揮手、門廊燈 |
| Learning Corner | 圖書館／小學校園 | 學習活動入口；不另收解鎖費 | 校車接送、書本借閱 |
| Farm Meadow | 小農舍與既有農場入口 | `meadow`，花朵 | 拖拉機耕作演出、皮卡載貨 |
| Market Street | 預留兩個獨立店面槽位 | `market-square`、`bakery` | 貨車卸貨、麵包店取貨 |
| Town Square | 開放廣場 | `city-center`、`rainbow-fountain` | 巡邏、噴泉水花、居民停留 |
| Play Park | 草坪與小徑 | `playground`，花朵 | 冰淇淋車停靠、遊樂設施動作 |
| Garage Yard | 車庫與出入場緩衝區 | 車輛部署位置；工程車工作角落 | 停車、出車、積木裝卸 |
| Woodland Hill | 小池塘、林間空位 | `orchard`、`castle-hill` | 露營車、果園載貨、城堡迎賓 |

每個大型物件有自己的地基與安全間距，麵包店不能疊在市場上，城堡不能蓋住道路。未放置的可購買建築呈現草坪槽位，不放一棟與已擁有物件幾乎相同的半透明建築誤導孩子。

### 3.3 橫直向與小螢幕

採用相同語意區域的兩套配置，而不是把同一張大圖無限制縮小：

- 橫向：4 欄 × 2 排區域，完整道路環線。
- 直向：2 欄 × 4 排區域，道路重新排版，仍顯示全部 8 區。
- 旋轉螢幕時保存物件的區域與槽位，不儲存螢幕像素座標。
- 平板優先顯示明確建築輪廓與車輛；手機用較短標籤與圖像，詳細名稱留在選取卡片。
- 動態小車不是唯一選取入口。手機可從車庫卡片選取／收回，無須追著小圖案點。
- 一般按鈕與放置選項的設計目標為至少 44 × 44 CSS 像素；這是本專案目標，不宣稱已完成無障礙認證。

## 4. 放置玩法：先選收藏，再選位置

### 4.1 放車

**我的車 → 點已擁有的車 → 點亮起的出車／停車位置 → 放入城市 → 自動出發。**

- 卡片狀態只有「在車庫」「在城市」「暫停中」。
- 拖放可作為第二種操作，但兩次點選必須能完成所有放置功能。
- 車輛放在有效位置後先等待安全空檔，再駛入主路，不能直接出現在另一台車上。
- 使用者可再放第二台、第三台，前面的車持續運作。
- 4.0 完整首發驗收必須支援目前全部 14 種車同時部署，不能用「多車」名義只讓一台跑。
- 不要求孩子把車拖到精確像素；有效區域有吸附與清楚預覽。
- 每個既有車輛 ID 對應一個可部署實例；同一台車不能重複複製出無限台。
- 「把我的車放進城市」提供批次放置，但需要一次確認，不能自動買車。

### 4.2 放建築與裝飾

**我的收藏 → 建築／裝飾 → 選擇擁有的物件 → 點有效槽位 → 完成。**

- 建築僅能放入相容的区域槽位；例如市場和麵包店有各自槽位，不能互相覆蓋。
- 花朵等小裝飾至少提供 12 個槽位，支援既有 12 格花園中的所有已擁有花朵。
- 裝飾依花園格位產生穩定實例 ID，例如 `legacy-flower-0`；兩朵同色花不是同一個實例。
- 裝飾從舊花園映射至城市的顯示不消耗第二次金幣，也不新增第二份可交易資產。
- 預覽時顯示占用範圍；已占用、道路及不相容區域不可放置。
- 放置失敗返回原處，不扣幣、不刪收藏。

### 4.3 移動、收回與編輯

選取後提供「移動」「收回收藏」「查看」。不把「收回」叫做刪除或賣出。

- 移動與收回免費，擁有權不變。
- 編輯模式暫停車輛與居民，避免物件位置改變時發生穿越或消失。
- 關閉編輯模式後重建可到達的停靠點，再恢復移動。
- 收回建築只關閉該建築在城市中的停靠／演出，不回收既有土地權益。例如收回 meadow 的城市顯示不會減少正式農場的床位。
- 收回正被拜訪的建築，車輛安全結束演出並選擇其他目的地；不能卡住等待不存在的建築。
- 清空城市只能清空布局，必須確認；絕不清空錢包或資產。

## 6. 自動城市模擬

### 6.1 每台車獨立狀態

每一台車有獨立的部署 ID、車種、起始位置、路段、沿路距離、目的地、速度、等候計時、互動状态及可重現的隨機種子。

狀態循環：

**車庫 → 出車等待 → 行駛 → 路口讓行／停靠等候 → 停靠 → 執行互動 → 再選目的地 → 行駛。**

全域暫停、單車暫停、編輯、頁面隱藏、素材失敗及收回收藏均有明確處理。沒有有效目的地時，選擇免費停靠點或安全停車，不拋例外或無限重試。

### 6.2 隨機但合理，不是亂飄

- 從已放置、可到達且適合車種的停靠點選擇下一站。
- 優先嘗試相應用途的地點，但保留一般拜訪的變化。
- 至少記住上兩個目的地，降低同一對地點連續來回的情況。
- 同時多車不共用一份「目前目的地」或單一行駛座標。
- 同一個測試種子能重現路線選擇，方便重現卡車、錯誤轉向或碰撞問題。
- 每車的啟動與停留時間錯開，不讓所有車同時起步、同時停靠。

### 6.3 道路與避免碰撞

第一版用兩個相連的單向圓角環線，加各區的短停靠支線。這是玩具車軌道，不是複雜交通模擬。

- 以共用道路圖定義路段、連接點、轉彎曲線、停靠口及路口資源。
- 直路接轉彎的切線連續，不用先水平再垂直的瞬間 90 度折角。
- 依實際路徑長度取樣，車輛沿弧長前進，避免曲線中忽快忽慢。
- 前車距離、車身長度與最小安全間隔一起限制後車前進。
- 車輛駛入路口前先預約出口空間，不能停在路口中心形成循環等待。
- 停靠區在主路之外，不讓一輛買冰淇淋的車堵住整條城市。
- 路口依到達順序讓行；同時到達用穩定 ID 排序，避免抖動。
- 沒有碰撞爆炸、鳴笛處罰、損壞、修車費或扣幣。
- 不能用不斷瞬移回出發點掩蓋塞車問題。異常應能在診斷紀錄中辨識。

### 6.4 解決現有車輛移動問題

- 同一個 `requestAnimationFrame` 主循環管理所有車輛，不為每一台另建一個無限制循環。
- 以時間差計算移動，不用「每幀增加固定像素」。
- 彎道降低速度、出彎恢復，進出停靠區平滑減速／加速。
- 車輛使用與地圖視角一致的方向圖集或可轉向模型，不把側視車貼圖整張旋轉到倒立。
- 製作 8 個方向的車身姿態；轉向只改方向和位置，不改地圖鏡頭。
- 每幀僅更新動態圖層，不重建整個城市 DOM，也不每幀讀寫 localStorage。
- 暫停或切到背景後停止移動；回來重置時間基準，不把背景時間一次補算成瞬移。

以上計時與頁面可見性要求採用標準瀏覽器機制，參考文件列於末尾；實際 iPad 表現需另外驗證。

## 7. 互動必須看得懂，不只是跳出一個圖示

| 配對 | 實際畫面演出 | 完成後 |
|---|---|---|
| 校車＋校園 | 校車進站、門打開、兩個角色走下來、關門 | 選下一站 |
| 皮卡＋農場／市場 | 角色搬籃子到車斗，或從車斗搬下 | 車斗內容更新，再出發 |
| 冰淇淋車＋公園 | 側窗開啟、居民靠近、點心交付、短暫愛心 | 居民回去遊玩 |
| 砂石車＋工程角落 | 斗抬起、幾個積木落入指定範圍、斗降下 | 車子離開，物件有數量上限 |
| 挖土機＋工程角落 | 挖臂抬起、移一塊積木、放到旁邊 | 等一段時間再工作 |
| 拖拉機＋農場 | 沿田邊走一小段，短暫澆水／耕作效果 | 回到停靠點 |
| 普通車＋麵包店 | 停到側邊、門開、麵包袋交给居民或放進車 | 車輛再離開 |
| 車輛＋噴泉 | 居民停留，水花有短暫起伏 | 不擋路，不改速度到失控 |
| 車輛＋城堡 | 城門打開，迎賓角色揮手，旗幟輕擺 | 車輛駛向下一個開放地點 |

同時最多兩組主要角色互動演出；其他車可以繼續行駛或排隊。單次演出初始設計為約 2–4 秒，需以真實播放調整，不是倒數要求。額外音效預設安靜，經明確點選後才開啟，且不與故事或提示朗讀重疊。

**城市自動動作是視覺遊戲，不自動發金幣、不推進正式作物進度、不消耗已儲存貨物。** 原本農場的真實收成／送貨仍透過既有具去重檢查的操作領取，城市卸貨演出不能變成另一個領取入口。

首次配對可以解鎖不具金錢價值的互動徽章；它不是每次循環都發的獎勵，也不是新增的一種貨幣。

## 8. 美術規格：Premium Cozy Toy Town

### 8.1 可辨識的視覺語言

- 固定略俯視玩具城視角，圓潤但結構清楚。
- 奶油色底板、草地綠、蜜桃、淡藍、薰衣草色；文字另有足夠對比，不讓全部元素都淡到看不清。
- 車輛像有份量的玩具模型：明確輪胎、車頭、車窗、車斗、挖臂、巴士座位窗。
- 建築有獨特輪廓與入口：校園、麵包店、車庫、市場、城堡不能只換顏色與文字。
- 陰影方向一致，資產比例一致，道路不能被裝飾遮住。
- 地圖、建築、車輛卡片與居民不要用作業系統 emoji 充當正式美術，也不要裁切大型海報當模糊的遊戲貼圖。
- 孩子要在真實平板尺寸認出車種，不是放大十倍的設計稿才看得懂。

### 8.2 首發美術清單

| 項目 | 交付要求 |
|---|---|
| 城市底板 | 橫向、直向兩種排列；語意区域和資產 ID 相同 |
| 14 種車輛 | 每種自己的輪廓、卡片圖，以及行駛所需的 8 方向姿態 |
| 9 種已販售土地／建築 | 依區域對應獨立制作，可放置、不共用錯誤建築外觀 |
| 常設地標 | 家、校園、農舍、車庫及林間池塘，与付費資產的狀態有區別 |
| 4 類花朵 | 可重用既有種類，但用清楚可縮放的城市版本 |
| 居民 | Pip、Benny、Milo 等少量角色，至少站立、走路、揮手與搬運姿態 |
| 互動附件 | 書本、麵包袋、貨物籃、積木、水花、冰淇淋、短暫愛心 |

素材對照表必須記錄 asset ID、方向、錨點、占用邊界、停靠點及預覽來源。素材缺失應有清楚的佔位畫面，不能用錯誤車種頂替並宣称美術完成。

美術驗收的關鍵不是圖檔有幾張，而是相鄰建築能分辨、14 種車能分辨、移動與停靠演出在真實尺寸有說服力。

## 10. 擁有權與布局存檔

### 10.1 單一擁有權來源

- 正式錢包繼續使用 `kgj-kingdom-v1`。
- 正式布局新增獨立 key：`kgj-city-v4-layout`。
- 測試錢包沿用 `kgj-kingdom-city-v2-test-wallet`。
- 測試布局使用不同 key：`kgj-city-v4-test-layout`。
- 布局只能引用已擁有的車、土地和花朵；常設地標由静態場景定義，不偽造購買。
- 不把车辆位置寫進閱讀紀錄，不變更寫字或數學存檔命名空間。

### 10.2 布局字段

| 字段 | 用途 |
|---|---|
| `schemaVersion`、`revision` | 版本、衝突檢查及未來遷移 |
| `vehiclePlacements` | 車輛資產 ID、出車口／停車位、是否啟用、偏好區域 |
| `buildingPlacements` | 已擁有資產 ID、區域 ID、槽位 ID |
| `decorationPlacements` | 花朵或裝飾的穩定實例 ID、槽位、合法方向 |
| `simulationSeed` | 可重現的行駛選擇；不用於發放金錢 |
| `preferences` | 城市暫停、少動作與音效偏好 |
| `interactionBadges` | 去重的非金錢互動徽章 |
| `updatedAt` | 資料變更時間，不用於離線收益 |

高頻位置在記憶體中更新。部署、收回、移動、重要設定改變後才寫存檔。車停在哪個區域可以存，逐幀坐標不必每次落盤。

### 10.3 初次開啟與旋轉

- 舊錢包一筆金幣都不重算，既有車輛全部留在車庫。
- 首次可提示「把我的車放進城市」，按下後才批次部署；不要擅自自動買或增加車。
- 既有建築／花朵可映射到建議槽位，用户可免費收回或重排，不能因地图变小就丟掉資產。
- 横直向切換時短暫暂停，以 slot ID 映射位置；車輛回到相應停靠口再继续，不拉扯或瞬間穿樓。
- 修改布局前保存恢復快照；讀取失敗不直接覆蓋成空白城市。
- 其他分頁發生購買／還原時重新檢查擁有權。無對應資產的布局引用保留在隔離區並提示，不製造免費資產。

### 10.4 備份與測試

家長區新增「匯出完整城市」：包含既有錢包快照與 4.0 布局，標明不包含尚未同步的寫字墨跡等其他模組內容。匯入要驗證版本、ID、槽位、重複實例和正式／測試命名空間，確認後再套用。

測試模式繼續有 5,000 起始金幣與完整目錄解鎖。重設測試城市要一起重設測試布局，但正式存檔、花朵與金幣完全不動。既有測試購買不因改版自動清除。

這仍是每個瀏覽器／裝置本機儲存，不能說分享網址就是同步孩子的城市。

## 11. 工程拆分

採用獨立模組，避免在舊畫面上疊加更多相互監看的修補腳本。

| 模組（擬定） | 職責 |
|---|---|
| `city-v4.html`／`city-v4.css` | 全貌畫面、不同方向版面、收藏抽屜及設定 |
| `city-layout-v4.js` | 8 區位置、停靠點、槽位、合法性與橫直向映射 |
| `city-placement-v4.js` | 放置、預覽、移動、收回、布局存檔和去重 |
| `city-simulation-v4.js` | 多車状态、目的地選擇、路線、距離、讓行及暂停 |
| `city-interactions-v4.js` | 車種與建築配對、居民與道具演出、冷卻及並行上限 |
| `city-renderer-v4.js` | 静態場景與動態角色分層，僅更新變動部分 |
| `assets/city-v4/` | 建築、車輛方向圖集、居民與演出素材及 manifest |
| `tests/city-v4/` | 布局／模擬單元測試、真實瀏覽器流程、視覺回歸與存檔遷移 |

原本 `kingdom-core-v2.js` 負責真實購買與金幣；4.0 的模擬器不直接加錢。原本 `selected` 可繼續作為車庫高亮記錄，但不再限制部署數量。

遇到旧的 `kingdom-v1.js` 資產圖集、舊文字說明或导航与 City4 不一致，应列出明确修改范围，不用错误的旧图片替换新车。4.0 的主城市与收藏面板由同一份 asset manifest 渲染。

## 14. 安全、動作與聲音控制

全域 Pause City 隨時可見。系統 Reduce Motion 或應用的少動作模式下，車輛默认停在部署點；孩子可透過靜態互動卡查看「送達」「領書」等回饋。不可為了達成自動行駛而忽略動作設定。

不使用刺眼閃光、持續警報、破壞城市、強迫回訪、付費隨機獎勵、過期作物或連續登入懲罰。背景行駛不啟動麥克風、不上傳孩子資料、不加第三方分析追蹤。

W3C 的無拖曳替代與自動動作暫停指引，是本案操作規格的設計依據，而不是對產品做法的預先認證。

## 15. GitHub 與發佈規則

1. 本文件先存入 repo；本次文件交付不改動主網站版本。
2. 實作使用獨立分支，例如 `feature/city-4-living-board`，不 force-push，不逐段覆蓋正式入口讓孩子遇到半套版本。
3. 先完成可驗收候選版本與素材，再以同一完整變更切換 `city.html`；旧網址與 `test=1` 仍需有效。
4. 每個需要變更的 script、stylesheet、asset manifest 要有一致的新版本識別，不僅在 HTML 網址加參數。
5. 備份正式錢包与布局，核對購買、三種學習獎勵以及測試模式。
6. 合併後確認 GitHub Actions 的正確 commit；再打開實際 Pages URL，檢查新版本標記與關鍵素材載入。
7. 最终交付先給可玩的 GitHub Pages 链接，再給原始碼／變更說明；ZIP 只作附加。
8. 若只是規格或美術預覽，連結要明確標示用途，不能称为已更新的遊戲。

**這份規格本身沒有新增 City 4.0 的可玩連結。**

## 16. 60 秒示範腳本

使用獨立測試城市，先買紅車、校車、皮卡、市場與麵包店。打開城市，全貌始終可見。

依次把三台車放到不同出車口。紅車拜訪家和圖書館，校車到校園上下客，皮卡往農場與市場送貨。孩子不按 Drive here，也能看到各自輪流工作。

把麵包店放進店面空位，再把一朵已擁有的花放在門口。普通車之後可能到麵包店停靠，居民帶著麵包袋離開。點暫停，三台車都停止；收回一台車後，另外兩台繼續；重新整理仍保留布局。

這段示範應在真實尺寸的 iPad／平板瀏覽器畫面錄製。沒有完成這段整體體驗，就不把「單畫面＋多車＋放置＋自動互動」報告為完成。
